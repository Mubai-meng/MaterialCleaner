# ADR 0015：恢复失败关闭与证据约束操作范围

- 状态：已接受
- 日期：2026-10-10
- 范围：MediaProvider 恢复熔断总账、强杀操作范围、DataBus 游标水位、重试计数生命周期、诊断命令收尾

## 背景

此前恢复与清理逻辑对正常路径建模精细，但多条异常路径可绕过声称的安全约束：

第一，恢复总账先强杀后补写，`persist` 失败仅日志；损坏总账 `starting fresh` 清零，跨重启熔断失效。

第二，`optInt/optLong` 宽松解析把 `{}`、类型错误、负轮次静默归零；`clear()` 用跟随链接的 `File.exists()`，悬空符号链接下谎报成功，与读取的 `NOFOLLOW` 语义分叉。

第三，强杀按全用户×全已安装包执行，观测证据仅做日志对照；准入守卫与最终操作依据两份独立扫描快照。

第四，重试 `.attempts` 计数只在毒丸路径清理，成功路径残留并无界累积；诊断命令超时收尾存在 reader/主线程对非线程安全缓冲区的竞态。

## 决策

1. **预先记账**：组装新账 → 落盘成功 → 更新内存 → 执行强杀；写失败禁杀。杀后崩溃只会多记不少记，偏保守方向。
2. **总账三态 + 语义校验**：`Absent/Ok/Corrupted` 区分确认不存在与不可确认；`parseLedger` 显式校验 schema（缺失/类型错/负轮次/失配一律腐败，`{}` 不是空账本）；`clear()` 改 `NOFOLLOW` 语义并复验路径消失。腐败态强制 `PROBE_ONLY`，只有清账成功才退出。
3. **操作范围收敛**：操作集合 = 观测 `(package,userId)` ∩ 该用户下已安装；无观测依据不杀。单次执行前扫描贯穿准入、记账与操作。
4. **计数生命周期**：成功/跳过终态在游标提交成功后清除计数，清除失败不回退游标；孤儿计数 GC 兜底（计数对应事件已不在队列则删）。
5. **命令收尾加固**：`synchronized` 包读写，`join` 未果则 `close` 输入流解除阻塞后二次 join；超限继续排空丢弃。

## 后果

- 绕过方向全部掰向保守侧（少杀、少删、停住），且保守侧可观测（独立游标故障告警、范围日志、`readError` 标志）。
- ` Corrupted` 总账的设备需人工介入清账后才恢复破坏准入；长期 `UNREADABLE` 游标停止源事件清理（保安全，接受队列增长，另立告警）。
- 风险：预先记账在“记账成功、强杀前崩溃”时误耗一轮（保守方向，可接受）；游标损坏仍不承诺完整历史重放（已接受边界，见 FAQ）。

## 拒绝事项（含理由）

1. **拒绝游标镜像/独立提交日志**：双写一致性引入新故障面，与已接受的有限重放边界重复，复杂度与收益不成比例。
2. **拒绝 PID 精确杀**：平台 API 粒度为包级，伪装精确只会带来虚假保证；以观测交集收敛到 API 允许的最小范围为止。
3. **拒绝通用 GC/重试框架**：孤儿清理复用既有 prune 节流，不建新抽象；重试阈值与毒丸判定本次不动。
